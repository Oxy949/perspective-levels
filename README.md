# Perspective Levels

Модуль для Foundry VTT 14, который добавляет визуальную перспективу на уровне (`Level`) сцены:

- настройки хранятся на конкретном `Level` через flags;
- на одном уровне можно оставить обычную сетку, на другом включить перспективную;
- токены визуально масштабируются по Y-позиции между двумя якорями;
- порядок отрисовки токенов пересчитывается по перспективной глубине от нижней точки токена;
- размер клетки перспективной сетки настраивается отдельно для каждого уровня;
- дистанции считаются по клеткам нарисованной перспективной сетки, а не по экранным пикселям;
- есть калибратор с двумя псевдо-токенами-якорями на canvas.

## Установка

1. Распакуйте папку `perspective-levels` в:
   `FoundryVTT/Data/modules/perspective-levels`
2. Перезапустите Foundry.
3. Включите модуль в мире.

## Использование

1. Откройте сцену с Scene Levels.
2. Выберите нужный уровень.
3. Откройте настройки уровня (`LevelConfig`).
4. В блоке **Перспектива уровня** включите **Использовать перспективу на этом уровне**.
5. Нажмите **Открыть калибровку якорей** или кнопку с иконкой в инструментах токенов.
6. Перетащите дальний и ближний якоря. Их масштаб задаётся ползунками.
7. Нажмите **Сохранить на уровень**.

## Важное ограничение

Модуль перехватывает измерение дистанций через `BaseGrid#measurePath` и `Token#measureMovementPath`, когда на текущем уровне включена опция **Считать дистанции по перспективной сетке**. Расчёт теперь идёт по клеточным координатам самой нарисованной перспективной сетки: один перспективный квадрат равен `scene.grid.distance` Foundry — например 5 ft в D&D-сцене. Горизонтальный и вертикальный экранный шаги не обязаны быть равны: точка сначала переводится в координаты перспективной сетки, затем расстояние считается в клетках с учётом правила диагоналей сцены (`grid.diagonals`).

Ограничение: модуль не переписывает коллизии стен, Regions и pathfinding. Если Foundry или система возвращает бесконечную стоимость движения из-за препятствия, модуль сохраняет блокировку; если есть terrain/movement multiplier, он пытается сохранить исходное соотношение cost/distance.




## v0.2.14

- Переделана контурная обводка токенов: больше не используется штатный `OutlineOverlayFilter` с `knockout:false`, потому что в Foundry он может скрывать/прозрачнить исходный арт.
- Обводка теперь использует отдельный MTE-style shader на базе `AbstractBaseFilter`: токен остаётся видимым, а цветной контур считается по альфе PNG.
- Квадратная рамка Foundry скрывается только при активной перспективе уровня и только там, где включается контур.

## v0.2.13

- Исправлен крэш `can't access private field or method: object is not the right class` при создании MTE-style outline.
- Обводка токена больше не наследуется от `OutlineOverlayFilter`: используется штатный `OutlineOverlayFilter.create({ knockout: false })` в wrapper-патче `Token#_refreshState`, поэтому Foundry v14 не падает на приватных static-полях shader-класса.
- Логика осталась как в multi-token-edit Scenescape по месту применения: стандартная квадратная рамка скрывается, outline живёт в `token.mesh.filters` и включается только при активной перспективе уровня.


## v0.2.12

- Убран самодельный контур из множества смещённых спрайтов.
- Контур выбранного токена теперь сделан как в multi-token-edit Scenescape: wrapper `Token#_refreshState` скрывает стандартный `token.border` и добавляет к `token.mesh.filters` модифицированный `OutlineOverlayFilter`, который обводит PNG по альфе и не скрывает саму текстуру токена.
- Обводка включается только когда на текущем уровне включена перспектива; вне перспективного уровня стандартная рамка Foundry остаётся как обычно.

## v0.2.11

- Исправлена ошибка прав у игроков при перемещении токена: сохранение перспективной сортировки `TokenDocument.sort` теперь выполняет только GM-клиент. На игроках сортировка применяется локально для визуального порядка, но не отправляет `Scene.updateEmbeddedDocuments("Token", ...)`.
- Сохранение высоты после Shift-drag теперь проверяет право пользователя на обновление конкретного `TokenDocument`, чтобы не ловить `lacks permission to update Token`.
- Квадратная рамка токена скрывается на перспективном уровне; вместо неё при выделении, наведении и таргете рисуется альфа-контур по PNG-текстуре токена цветом стандартной рамки/отношения.
- Добавлен alpha/pixel-perfect `Token#getShape`-патч по принципу MTE: попадание мыши по токену дополнительно проверяется через `mesh.containsCanvasPoint`, а не только через прямоугольник.


## v0.2.16

- Исправлена MTE-style обводка: фильтр теперь использует высокий порог альфы как в multi-token-edit, поэтому прозрачный прямоугольник текстуры больше не заливается цветом рамки.
- Обводка стала ближе к реальному контуру PNG и не должна превращаться в жёлтый квадрат вокруг токена.
- WASD-движение по перспективной сетке теперь отправляет обновление токена с `animate: true`, чтобы Foundry проигрывал обычную анимацию перемещения.

## v0.2.15

- Контур токена стал плотнее: shader теперь оставляет исходный арт непрозрачным и рисует отдельную альфа-маску outline вместо полупрозрачной дымки.
- Убрано автоматическое серверное сохранение перспективной сортировки сразу после drag/движения, чтобы дальняя анимация Foundry не обрывалась телепортом. Сортировка остаётся локальной и пересчитывается при обновлении canvas.
- Добавлен перехват `TokenLayer#moveMany` для клавиатурного WASD-движения: при включённой перспективе шаг считается по перспективной сетке, а не по обычной прямоугольной сетке сцены.


## v0.2.17

- Переписан Shift-drag для полёта в FVTT 14: при зажатом Shift токен можно вести по экранной горизонтали и вертикали, а вертикальная дельта сохраняется в `TokenDocument.elevation`.
- Масштаб токена с высотой теперь считается не от видимой Y-позиции, а от восстановленной точки на земле под токеном, поэтому при полёте размер не "едет" по перспективной сетке.
- Расчёт дистанций учитывает реальную `elevation`: экранная высота не должна одновременно считаться и глубиной по перспективной сетке, и Z-дистанцией.
- WASD-движение для уже поднятых токенов сохраняет визуальную высоту, а не опускает их обратно на сетку.


## v0.2.7

## v0.2.6

- Во время перетаскивания порядок пересчитывается по нижней точке drag-preview, поэтому пересечение токенов должно менять порядок отрисовки не только после drop.
- После завершения перетаскивания новый порядок сохраняется через `Scene#updateEmbeddedDocuments("Token", ...)`, чтобы сортировка была синхронизирована и переживала перерисовку canvas.
