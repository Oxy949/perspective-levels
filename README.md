# Perspective Levels

Модуль для Foundry VTT 14, который добавляет визуальную перспективу на уровне (`Level`) сцены:

- настройки хранятся на конкретном `Level` через flags;
- на одном уровне можно оставить обычную сетку, на другом включить перспективную;
- токены визуально масштабируются по Y-позиции между двумя якорями;
- размер клетки перспективной сетки настраивается отдельно для каждого уровня;
- дистанции считаются по клеткам нарисованной перспективной сетки, а не по экранным пикселям;
- есть калибратор с двумя псевдо-токенами-якорями на canvas.

## Установка

1. Распакуйте папку `perspective-levels` в:
   `FoundryVTT/Data/modules/perspective-levels`
2. Перезапустите Foundry.
3. Включите модуль в мире.

## Использование

1. Откройте сцену с Scene Levels.
2. Выберите нужный уровень.
3. Откройте настройки уровня (`LevelConfig`).
4. В блоке **Перспектива уровня** включите **Использовать перспективу на этом уровне**.
5. Нажмите **Открыть калибровку якорей** или кнопку с иконкой в инструментах токенов.
6. Перетащите дальний и ближний якоря. Их масштаб задаётся ползунками.
7. Нажмите **Сохранить на уровень**.

## Важное ограничение

Модуль перехватывает измерение дистанций через `BaseGrid#measurePath` и `Token#measureMovementPath`, когда на текущем уровне включена опция **Считать дистанции по перспективной сетке**. Расчёт теперь идёт по клеточным координатам самой нарисованной перспективной сетки: один перспективный квадрат равен `scene.grid.distance` Foundry — например 5 ft в D&D-сцене. Горизонтальный и вертикальный экранный шаги не обязаны быть равны: точка сначала переводится в координаты перспективной сетки, затем расстояние считается в клетках с учётом правила диагоналей сцены (`grid.diagonals`).

Ограничение: модуль не переписывает коллизии стен, Regions и pathfinding. Если Foundry или система возвращает бесконечную стоимость движения из-за препятствия, модуль сохраняет блокировку; если есть terrain/movement multiplier, он пытается сохранить исходное соотношение cost/distance.


## v0.2.0

- Проведён модульный рефакторинг: entrypoint оставлен тонким, логика разнесена по `scripts/modules`.
- Геометрия перспективы, измерения дистанций, масштабирование токенов, PIXI-сетка, калибратор, UI настроек и runtime patches теперь живут отдельно.
- Добавлен отсутствующий `parseColor`, из-за которого перспективная сетка могла не отрисовываться.
- Drag-preview защищён от циклического обхода и накопительного scale при серии перетаскиваний.
- Публичный `PerspectiveLevels` API сохранён и дополнен namespace-блоками `config`, `projection`, `measurement`, а также доступом к overlay/calibrator.

## v0.1.1

- Исправлено накопительное масштабирование токенов при перемещении/обновлении.
- Масштаб токена теперь считается от сохранённого базового `mesh.scale`, а позиция токена не входит в signature.
- Интерполяция размера токена стала линейной между дальним и ближним якорями.
- Масштаб считается по нижней точке токена, а не по центру.


## v0.1.2

- Добавлен live-скейл токенов во время перетаскивания и drag-preview.
- Исправлена точка расчёта размера токена: используется логическая нижняя точка токена, а не `bounds.bottom`, который меняется после визуального скейла.
- Добавлена опция уровня **Считать дистанции по перспективной сетке**.
- Дистанции считаются через обратную проекцию в координаты перспективной сетки.
- Перехвачены `BaseGrid#measurePath` и `Token#measureMovementPath`; результат сохраняет структуру Foundry `GridMeasurePathResult`.


## v0.1.4

- Переписан расчёт дистанций: теперь он считает не пиксели и не обычную прямоугольную сетку Foundry, а клетки текущей перспективной сетки.
- Один нарисованный перспективный квадрат равен одной единице сетки сцены (`scene.grid.distance`).
- Учитываются разные экранные масштабы по горизонтали и вертикали: вверх-вниз и влево-вправо проходят через обратную проекцию в координаты перспективной сетки.
- Добавлена настройка уровня **Масштаб клетки**: меняет размер клетки перспективной сетки на ближнем крае карты; дистанции следуют за этим размером.
- Измерения используют правило диагоналей Foundry (`CONST.GRID_DIAGONALS`) там, где это возможно.
